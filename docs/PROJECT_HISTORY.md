# 项目历史

> 本文件根据项目产物和现有实现整理。原生产目录此前没有 Git 历史，因此这里记录的是阶段演进，而不是逐提交变更日志。

## 2026 年 5 月：从周报阅读压力到可用 MVP

- 从约 30 名员工的多周周报中建立按人员、周次和部门的统一数据结构。
- 形成周报质量评分、个人成长趋势、老板必读周报和管理注意力队列。
- 使用 Kimi 分析周报中的结果、问题、复盘、计划和情绪信号。
- 将一条粗粒度问题拆成多个可勾选的任务候选，并接通飞书任务创建。
- 完成飞书 SSO、老板视角、员工个人页和同部门可见范围的第一版。
- 采用“本地预处理 + 静态页面发布 + 服务器互动数据”的技术路线，避免在小规格 ECS 上实时运行重型 AI 管线。

## 2026 年 6 月：自动化、互动和跨周闭环

- 接通飞书原生汇报读取与 Excel 增量导入，支持补交周报按人员和周期 upsert。
- 建立周期快照，让历史周报、历史 AI 点评和当周任务建议可以回看。
- 增加评论、点赞、全员分享、AI 追问和通知中心，并将互动写入 SQLite。
- 完成飞书任务创建、创建者关注、任务回调和任务闭环状态同步。
- 增加周五复盘提醒、周一更新通知、个性化文案 outbox 和活跃日志。
- 把 HRBP 的协同 360 评分整合进成长 OS，支持评分对象配置、周期结果和管理看板。
- 增加组织成长贡献者、闭环力、机制型成员和 AI 协同清晰思考者等分析维度。

## 2026 年 7 月：管理会议与稳定运营

- 增加部门周会议题和公司月度经营复盘页面，支持从事实依据跳转回周报和任务。
- 将部门结构整理为国内、海外、商超和中后台管理中心等管理分支。
- 增加飞书用户授权到期预警、周一/周五巡检和发送后访问效果分析。
- 修复历史周期切换、外部顾问链接、任务编辑、通知标题和多角色权限等问题。
- 将月度会议页面纳入每周构建链路，为后续接入更多业务、财务和 Nexus 事实数据预留入口。
- 开始建立独立 GitHub 仓库，使代码迭代可以通过分支、PR、审阅和回滚完成；随后以脱敏代码与演示数据公开，生产数据继续与仓库隔离。

## 关键产品判断

1. AI 的价值不是替老板写 30 份点评，而是把管理注意力排序，让老板只看真正需要介入的事项。
2. 周报不是一次性文本，而是“承诺 -> 执行 -> 证据 -> 复盘 -> 新承诺”的组织上下文。
3. 任务被创建不等于闭环；只有任务完成、问题解决并形成机制沉淀，闭环才结束。
4. 情绪识别以鼓励和教练式提问为主，不把负面情绪直接变成惩罚标签。
5. 员工数据默认最小可见，老板驾驶舱、设置和任务闭环由授权名单控制。
